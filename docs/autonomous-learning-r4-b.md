# Autonomous Learning R4-B — EvaluationPacket builder foundation

Status: read-only builder and tests implemented; no production wiring or Evaluation execution. [R4-A](autonomous-learning-r4-a.md) schemas remain unchanged and authoritative. R3 immutable history remains the factual source.

## Boundary and exact resolution

`buildEvaluationPacket(input, readers, config?, authority?)` accepts only an exact project-local immutable hypothesis ref and bounded immutable TrialEvidence refs. Its reader interfaces expose `readExact` only, not live Experience, current Strategy projections or Session state. `FileTrialEvidenceV2Store` directly satisfies the evidence interface; `immutableHypothesisReader(FileDiscoveryHypothesisStore)` resolves the exact executable v2 hypothesis from immutable history (including historical parents), without consulting open/trusted state. The adapter rejects missing, conflicting or ambiguous identities.

Inputs/config are canonical-copied and deeply frozen before the first await. Every supplied ref is strictly validated, same-project bound, and resolved before selection. Resolved snapshots are immediately canonical-copied and independently checked against schema, scope, UUID and canonical fingerprint. Executable hypothesis validation recomputes its semantic fingerprint; TrialEvidence validation recomputes its content fingerprint. Unknown fields, missing artifacts, corruption, frozen v1 evidence/hypotheses, wrong project and conflicting duplicate UUIDs fail the entire build. Identical duplicate refs collapse to one entry. Invalid inputs are not silently dropped even when bounds would omit them. No assignment, raw source, discovery source or comparison Experience is dereferenced: their links are immutable historical provenance only.

An optional abort signal and opaque `isCurrent` guard fence entry, asynchronous resolution boundaries and final return. A false/stale guard or abort returns no packet. The builder does not read runtime/session identities or persist leases; these guards do not affect packet identity. Future consumers must revalidate publication authority separately. Injected readers are trusted immutable lookup boundaries, not proof supplied by callers: schema checks alone cannot establish filesystem provenance.

## Deterministic bounded selection

Builder version 1 config has exact fields `maxTrials` (integer 1–32, default 32) and `maxPacketBytes` (integer 1–131072, default 131072). Raw candidate input is bounded to R3's 4096-history cap, before dedupe. Individual evidence snapshots also respect R3's 16KiB limit; oversized snapshots fail closed rather than being truncated.

Resolve unique candidates in lexicographic UUID order (not filesystem, arrival or time order). Classify exact hypothesis UUID + fingerprint + scope equality as `included`; other same-project hypothesis evidence is `excluded-hypothesis`. Select included candidates first in UUID order, then excluded candidates in UUID order. Greedily admit each whole snapshot only if the complete canonical packet fits the configured UTF-8 byte budget, until the count limit. A candidate that cannot fit is omitted, and smaller later candidates may fit. Bounds are selection limits, not evidence-quality verdicts. Output entries are sorted by UUID and numbered `T1`…`Tn`, regardless of inclusion-priority selection order. There is no sampling threshold, score, confidence, recency gate or promotion rule. If no included fact fits, throw rather than inventing an empty/partial-valid packet; R4-A requires at least one included entry as a structural rule only.

Packet ID is deterministically derived from canonical `learningFingerprint({ builderVersion: 1, hypothesis, hypothesisSnapshot, refs, config })`, where refs are the entire sorted deduped exact candidate set, including omitted candidates. Use the first 128 digest bits and set UUID version-4/variant bits solely to satisfy R4-A's frozen UUID shape; this is a content-derived identifier, **not a random UUID**. Content fingerprint uses unchanged `learningArtifactFingerprint` over the final packet. Same exact inputs/config, stable resolved immutable snapshots and any input permutation yield identical packet bytes/ID/fingerprint. Identical duplicates have no identity effect. Changing config or omitted refs may change identity even if selected facts do not change. No timestamp/randomness enters construction; hypothetical digest collisions remain conflicts for future stores, never overwrite authority.

Only included WorkEpisodeIds contribute to `workEpisodeCount`; multiple Runs of one episode count once. `projectCount` is derived from included same-project facts and is 1 in this project-only schema. This is observational diversity, not statistical independence or sufficiency. `comparisonStatus` stays `unavailable`; even resolvable raw comparison refs are not analysis facts. Post-declaration counters and whole-Run outcome/cost facts stay unchanged, without causal attribution.

Finally run `validateEvaluationPacket` over the complete packet and return a detached deeply frozen object. No packet/result files, writer locks, model calls, scheduler jobs, EvaluationResults, Trust/Decision/Policy changes or production Host/extension wiring are added. The builder creates an in-memory frozen packet only.

## Verification and remaining R4-C requirements

Tests cover exact filesystem readers with no Experience directory, target exclusions, invalid refs/snapshots/v1/project bindings, corruption outside selected bounds, deterministic permutations/dedupe, count/byte limits, distinct/shared episode accounting, deep freezing/caller mutation and stale/aborted asynchronous reads. R4-A contract tests remain unchanged.

R4-C still needs an explicitly approved scope before implementation: immutable packet storage/exact lookup, capacity and retention policy, writer-lock atomic unique publication, durable input/output retry identity and crash reconciliation, operational model provenance and fenced publication authority. Evaluation enqueue/isolation/model invocation, EvaluationResult generation/storage and semantic analysis remain unimplemented; trust/promotion/Decision integration is a separate future boundary, not implied by this builder. Do not infer current eligibility from historical packet construction or expand R4-A's identity gate into promotion authority.
