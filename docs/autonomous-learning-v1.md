# Autonomous Learning v1 — approved Trial architecture reset

**Status: approved Trial reset architecture (PR #242 merged); R0/R1/R2/R3 complete. Slice 1, Foundation F1/F2 and Local Discovery D1/D2 remain implemented. Legacy T1 automatic execution is frozen; PR #241/T2 remains unmerged. R4-A Evaluation contracts are defined; Evaluation execution and autonomous trust remain pending.** Current production behavior is described by `architecture.md` and `behavior.md`; remaining migration is pending. The frozen SI v0.6/v0.7 and CPL v0.1/v0.2 documents describe legacy artifacts and trust during migration, not v1's future autonomy rules.

## 1. Boundary, purpose, and success

Autonomous Learning v0.1's same-Run signal, completion disposition, post-settlement admission and optional immediate learning Run are **rejected as the future architecture**. No per-Task reflection, judgment, or checkpoint belongs in normal execution. Delete that path during migration, not before replacement is safe. Git history retains its old design.

Goal: turn bounded factual Experience from real Human work into falsifiable advisory Strategy hypotheses; test them on suitable future real work, independently evaluate, autonomously trust or reject routine advisory knowledge, and revise it when reality changes. Success is observable changed future work with exact assignment + declared-policy attribution and reversible trust, not candidate count, self-reported improvement, provider-wire visibility, or an invented score. Non-goals: changing model weights, synthesizing fake Tasks, deciding user goals, automating consequential actions or Human Gates, expanding capabilities, creating a second Agent Loop, persisting hidden reasoning/transcripts, or guaranteeing causal efficacy from sparse evidence. Human-triggered SI/CPL remain legacy compatibility paths only while migration proceeds.

```text
Human goals/Tasks → Work Plane (Pi native Task Runs + Pindie semantic authority)
                         │ factual bounded Experience only
                         ▼
                 Experience store (project-local)
                         │ read-only selected evidence
                         ▼
       Learning Plane: scheduler → Discovery / Evaluation (native Pi Runs)
                         │              │
                         └→ immutable hypotheses, trials, evaluations, decisions
                                           │ trusted exact revisions only
                                           ▼
                          bounded portfolio projection → Work Plane advisory context

Reality → factual observations → Harness provenance/legality; no Learning Plane → Task truth edge
```

Human owns goals, learning budgets and exceptional override (pause, suspend, reinstate, reject); no routine promotion approval. Pi owns low-level `LLM → Tool → Result → LLM`, model invocation, tools and Session execution for all Runs. Harness owns factual selection, evidence, legality, scheduler/leases, immutable artifacts, decision gates and portfolio projection. The Discovery/Evaluation model owns semantic hypothesis meaning and evaluation, and authors bounded `useWhen`/`avoidWhen` and applicability hints in frozen packets; Harness owns only hard-fact eligibility and deterministic offer scheduling; free-form hints are not a machine classifier. The ordinary Work Plane Task model owns final semantic applicability and may explicitly declare one offered experimental Strategy through the existing Policy path or ignore it. Neither model owns factual provenance or authority. Reality owns reconstructable facts. Learning Plane depends on Work Plane Experience and trust-safe interfaces; Work Plane never waits for learning cognition. A small domain-specific persistent scheduler is allowed, separate from `PindieState` and the Human Task; it is neither a general task queue/workflow engine nor a second LLM loop.

## 2. Work Plane and Experience

Normal Tasks do real work and use only trusted advisory Strategy selections (or may select one explicitly labeled experimental revision when offered). Ordinary completion has **no `learningDisposition`, signal, reflection, or learning judgment**; verification, Gate and Task semantics are unchanged by learning success/failure. Task settlement writes factual episodic Experience outside `PindieState`: project namespace, operational WorkEpisodeId and Run identity, time, exact Strategy/revision declaration, declaration frontier and subsequent execution facts, verification outcome and coverage, relevant tool/mutation/error/cost facts, and evidence provenance, without raw transcripts or hidden reasoning. Failure to capture Experience is an isolated diagnostic, never a reason to revise completion truth or block delivery. An experimental offer adds bounded advisory context only when an open hypothesis is actually offered; there is never a global hypothesis catalog injected into every Task. This is the only intentional Work Plane Trial integration, not a learning signal, completion disposition or post-task reflection.

Work/Experience runtime owns a small durable operational `WorkEpisodeId` (also called TaskEpisodeId) outside `PindieState`: mint once when a new semantic Task occurrence is introduced or replaced, bind to project and the observed State transition/version, retain across Runs and restart for that occurrence, close on replacement/completion. The binding ledger contains identity/open-or-closed metadata only, never a second Task status, criteria or truth source. On startup reconcile the ledger against current State and settled Experience; replay the same occurrence without reminting, close stale episodes, and if a crash leaves occurrence identity ambiguous, skip offers/Trials until a new unambiguous transition instead of assigning a duplicate. This stable boundary is a Foundation prerequisite for once-per-episode assignment dedupe and independent-real-task attribution, not a Task ID added to semantic State.

Experience is evidence, **not cognition**. Bound record size and age/count per project; validate schema and exact namespace. Retain a recent diverse window, with deterministic age/size pruning and a protected set of refs needed by unresolved hypotheses, assignments, evaluations or trust decisions. Before pruning a source needed for a continuing claim, materialize the minimal exact factual support in an immutable evidence snapshot/TrialEvidence with source fingerprint and namespace; otherwise protect it. Discovery provenance may become historical (not promotion authority) after terminal reconciliation; trial decision support stays auditable in immutable TrialEvidence/Decision even after original episodes expire. Missing required live evidence fails closed for a new decision; trusted cognition survives pruning because its exact semantics and trust evidence live in separate immutable artifacts. Never preserve unbounded raw Experience just to maintain cognition.

## 3. Learning Scheduler and durable work

The LearningJob ledger is small, bounded operational metadata, not Task State: kind (`project-discovery`, `revision-discovery`, `evaluation`, `portfolio-maintenance`, `global-discovery`), scope, deterministic input fingerprint, stable job key, state, attempt, eligible-after, budget reservation, lease owner/expiry and terminal receipt reference. States: `pending → running → completed | cancelled`; an expired `running` lease returns to `pending` with the **same key** after reconciliation. Retries preserve identity; changed corpus/portfolio/hypothesis fingerprint makes a new key. Terminal jobs can be compacted only after corresponding immutable output/receipt is resolvable; a bounded hot receipt index plus exact lookup in immutable receipts/artifacts prevents rediscovery of an old fingerprint after ledger pruning. Store commits under a single writer lock with atomic writes; one learning model Run globally at a time. Work Plane never competes for its Task semantic State. Discovery, revision-discovery, Evaluation and portfolio-maintenance model Runs (and global discovery) run only in dedicated ephemeral/internal Pi Sessions or equivalently isolated AgentSessionRuntimes owned by Host/Learning Plane, never the active Human conversation Session. Each receives only its frozen bounded packet and restricted learning tools, inherits no Human transcript, appends nothing to the Human Session and publishes only validated artifacts/receipts. Pi still owns each low-level Agent Loop.

Cheap deterministic non-LLM enqueue/reconciliation hooks run after committed Experience, at Host startup/reload and at a safe idle transition; they never wait for model learning or block Task delivery. No timer or daemon is required. At safe idle opportunity and within Human-configured per-day token/time ceilings and per-job caps, claim the oldest eligible job; reserve budget before Pi invocation, account actual usage afterward, and enforce timeout/backoff and bounded retry count. No work if quota/Host authority or evidence is incoherent. Human input, an active Human Run, or project/Session change preempts learning: abort the isolated Pi Run if safe, release lease, retain idempotent pending work or cancel stale input; never delay Human delivery. Check generation and project binding before every output commit. Learning tools are read-only except narrow immutable artifact publication; they cannot call Task semantic tools or mutate project files. No LearningJob may mutate Task/Gate/verification truth. Repeated failures or capacity pressure are visible only when actionable; ordinary discoveries do not interrupt the Human.

## 4. Local discovery and hypothesis

Trigger project discovery deterministically after a configurable minimum of **new** eligible Experience not assessed by terminal DiscoveryReceipts, diversity across real Tasks/time/outcomes, available budget and no matching pending/running/completed key. The deterministic hooks above enqueue only when these gates pass; they do not ask a normal Task model to decide. Select a deterministic bounded corpus (e.g. stable sort by time/identity, stratified across outcomes/Tasks/Strategy exposure, per-stratum and total caps), excluding learning Runs, corrupt records and duplicates. Freeze a DiscoveryPacket: schema version, project ID, exact Experience refs and fingerprints, bounded factual summaries, selection rule/version, current trusted/open comparison catalog and fingerprints, eligibility counts, budget limits, packet fingerprint over canonical content excluding volatile timestamps. No raw Session transcript, source dump, tool-result body or hidden reasoning.

Start an independent native Pi Discovery Run with only that packet and a restricted result surface. It returns `none` (no useful/novel hypothesis), `covered` with exact frozen open-hypothesis refs (the new evidence is already represented), or a small capped set of structured proposals. Validate exact source membership, bounds, schema, identity, advisory-only semantics and lease before atomic publication. Write a terminal DiscoveryReceipt for `none`, duplicates/covered results, or published identities keyed by packet fingerprint; retrying identical input never creates new cognition. A crash before receipt reconciles immutable outputs by job/packet key; ambiguous partial writes are quarantined, not re-created blindly. Discovery is hypothesis generation, not an assertion of novelty or trust.

`StrategyHypothesis` is immutable, exact ID and canonical semantic fingerprint (schema, scope, logical ID, kind, base revision fingerprint, fields and source refs); lineage intent is `new` (no anchor) or `revise`: an exact open-hypothesis parent ref, preserving that parent's trusted base fingerprint when present, or an exact active trusted revision fingerprint with no hypothesis parent. It records project-local/user-global scope, `approach | modifier`, bounded rule/summary, `useWhen[]`, `avoidWhen[]`, **principles[]** (non-empty executable advisory rules), **expectedEffect** (observable change under stated conditions, not a causal superiority claim), **failureSignals[]** (falsifying regressions/contradictions), applicability/trial-search hints, source Experience refs with project and record fingerprints, and discovery packet identity. Reject empty/unobservable expected effects and unfalsifiable or authority-bearing claims; semantic usefulness is model judgment. No capability, permission, safety, Gate, verification, irreversible-action or Task-authority fields are learnable. Distinct immutable revisions never overwrite each other.


**Executable-hypothesis schema correction (R1 complete):** schema-v1 `StrategyHypothesis` lacks `principles[]`, while the existing `StrategyRevisionSemantics` / `createStrategyRevisionSelection` contract requires at least one principle. V1 remains readable, immutable and non-executable, with its original exact fields and canonical fingerprint unchanged; never reinterpret `trialHints` as principles. New production hypotheses are schema-v2, adding model-authored `principles[]` (1..8 non-empty strings, each <=256 characters). V2 semantic fingerprints include schemaVersion=2 and principles; both versions exclude discoveryPacketFingerprint as operational provenance. LearningArtifactRef stays schema 1 with exact ID + fingerprint. The pure executable guard checks legal v2 shape only, not trust, selection, assignment or Trial eligibility. Pure contract tests demonstrate compatibility with existing trial-status StrategyRevisionSelection semantics, without runtime selector/lease wiring.

Existing v1 artifacts remain readable immutable historical/comparison evidence but are not Trial-assignable. Do not mutate or auto-fill them. When later Discovery has exact new supporting evidence, it may publish a schema-v2 `revise` successor targeting the exact v1 parent and model-author the missing principles together with the rest of the revision semantics. The shared strict open-leaf projection closes a parent only through a valid exact child ref in immutable history with matching logicalId, kind and baseRevisionFingerprint. It applies equally to v1→v1 and v1→v2 chains, preserves every parent, and fails closed on orphan/malformed/cyclic lineage. Unrelated competing leaves still fail closed; no winner is selected. MAX_OPEN_HYPOTHESES=64 bounds projected leaves, not all historical artifacts; publication checks post-publication leaves, while MAX_DISCOVERY_COMMITS independently bounds immutable commit history. Experience protection reads full history rather than just leaves. No special migration model Run is required merely to make old cognition executable.

A `revision-discovery` job is separately keyed by the exact prior hypothesis fingerprint, `revise` Evaluation fingerprint and bounded evidence refs/fingerprints (including TrialEvidence new relative to the original discovery). Its native Pi Discovery Run sees those frozen inputs plus the exact parent and current comparison context; it may return none or one linked immutable revision hypothesis, subject to the same provenance, falsifiability, capacity, dedupe and receipt rules. It never edits the prior hypothesis. If no new evidence is yet available, the job remains pending until a later Experience hook supplies it; changed evidence creates a new input key, and identical retries do not duplicate a revision.

Reconcile before publishing: compare canonical fingerprints for exact duplicate; bounded semantic comparison against trusted revisions and open hypotheses to mark covered/overlapping or propose revision with exact parent. Model may suggest relation, but Harness enforces identity and scope constraints, one open competing revision per lineage initially, logical ID uniqueness, and per-project/global hypothesis and portfolio caps. If unsure, record covered/needs-review rather than silently inventing IDs. At capacity, schedule maintenance or notify Human; never evict a trusted revision automatically to make room.

## 5. Lifecycle and real-task Trial architecture reset

The Trial boundary is deliberately narrower than the previous T1/T2 design. A trustworthy Trial does **not** require proof that an advisory survived every Pi/provider transform or that hidden model cognition materially "used" it. Pindie can reliably own only reconstructable Harness facts: an assignment was committed, an exact experimental revision was successfully declared through the normal Policy tool, subsequent authorized work occurred after that declaration, and a settled Run produced factual outcome/verification/cost/error evidence. Provider delivery, attention and causal use are not observable Pindie facts and must not become promotion prerequisites.

Three identities have different jobs and must not be collapsed:

```text
WorkEpisodeId
  = scheduling / dedupe / independent-real-task diversity

Agent Run
  = one experimental placement + policy-declaration window

Run Experience
  = factual evidence unit for that placement
```

A `TrialAssignment` is created only after a **real coherent WorkEpisode identity exists**. There are exactly two initial-v1 placement seams:

1. **Preexisting Task at Agent Run start.** `captureRunStartEpisode()` already runs before Self-Improvement preparation, so bounded local `assignIfAbsent(projectId, workEpisodeId, ...)` may commit an assignment before the first model request.
2. **New Task created by `pindie_task_start` inside the Run.** After the semantic State and WorkEpisode ledger have committed, the awaited `tool_result` hook may perform the same bounded local assignment transaction before Pi's immediate continuation. If it succeeds, the current Run gains the experimental overlay before the next model decision. If it times out/fails, the original Task result continues unchanged.

Do **not** create a same-Run assignment after `pindie_task_replace`. Foundation F1 deliberately refuses whole-Run WorkEpisode attribution when one Run crosses Episode A → B; the replacement episode becomes eligible at its next Agent Run instead. Likewise, more than one Task occurrence in one Run yields no exact Trial attribution.

The assignment transaction selects at most one executable open hypothesis using hard facts only: project/scope, open lineage/trust state, prior committed assignments, bounded per-hypothesis attempt count/cooldown and stable fairness ordering. The committed assignment itself is the scheduling fact. Do **not** create a durable pre-bound reservation/hold, terminal no-offer receipt, recursive eligibility watcher or crash-recovered "maybe offered" state. Concurrency is resolved only where it matters: the assignment store atomically enforces at-most-one committed assignment per WorkEpisode and exact committed attempt counts. This architecture intentionally permits a **small strictly bounded local scheduling-I/O wait** at the semantic Task boundary; it never waits for a learning model, Discovery/Evaluation cognition, or provider instrumentation. Failures are fail-open for Human work.

After assignment commit, a **v1 ordinary-work overlay** binds the exact assignment to the current Session + Agent Run generation. The existing transient `context_with_system` seam may project the bounded UNTRUSTED / EXPERIMENTAL advisory **once** on the next model request from runtime-only state; it performs no Trial I/O, writes no Human transcript entry, and is not treated as a provider-delivery observer. For a preexisting Task this is the first request of the Run; for same-Run `task_start` it is the immediate post-tool continuation. Later Pi/provider transforms may still remove the advisory; this does not violate the architecture because rendering/delivery is not Trial evidence.

The advisory includes an exact `StrategyRevisionSelector` derived by the Harness from the immutable hypothesis. Reuse the existing `pindie_policy_set` path and exact revision-resolver pattern: if the model judges the hypothesis applicable, it must explicitly declare that exact revision in the correct `approach | modifier` role; the Harness resolves identity/status/semantics and records `revisionStatusAtRun = "trial"`. The resolver revalidates current assignment/hypothesis/trust legality at declaration; no filesystem watcher is required merely to keep a rendered advisory live. Do not reuse legacy SI `TrialRuntime` semantics that make `/trial` a special packet Run or suppress normal Task/trusted-policy preparation. No `pindie_trial_select`, decline tool or parallel selection state machine exists. Ignoring the offer is a complete non-selection outcome.

The reset uses a new **`TrialAssignment` schema v2** rather than reinterpreting T1's schema-v1 artifact. V2 contains only durable scheduling/provenance facts: schema/id/fingerprint, projectId, WorkEpisodeId, exact executable hypothesis-v2 ref, bounded comparison refs if already available, assignment-policy identity and createdAt. Session ID, Host ID, Agent Run generation and presentation expiry are runtime overlay facts, not durable assignment identity. Store v2 assignments in a distinct canonical namespace (or an explicitly version-partitioned store) so old T1 offer receipts/assignments can never satisfy v2 lookup by accident.

The executable schema-v2 StrategyHypothesis remains the cognition artifact; after validation, conversion to a runtime trial revision is mechanical. Use `logicalId` as Strategy ID, hypothesis ID/fingerprint as exact revision identity/fingerprint, `kind` as the role, and bounded advisory semantics from `summary/useWhen/avoidWhen/principles`; evaluation-only fields such as `expectedEffect`, `failureSignals` and `trialHints` remain in the hypothesis/evaluation packet rather than becoming authority-bearing Policy fields. This mapping must not add capabilities, permissions, Task truth or trusted status.

The existing RunExperience Policy attribution is the primary observable Trial seam. A Run is an **applied Trial observation** only when all of the following are factual and exact:

- the Run acquired a committed assignment through one of the two legal placement seams for its exact coherent WorkEpisode;
- the final successful Policy Snapshot contains the exact hypothesis revision in the assigned role with `revisionStatusAtRun = "trial"`;
- the final declaration has at least one subsequent ordinary non-policy execution call;
- the settled Experience remains attribution-eligible and binds the same WorkEpisode;
- the exact assignment and Experience can be resolved by fingerprint.

A trial revision selected and later replaced before settlement is conservatively non-eligible for v1; ordinary factual Experience remains valid. A rendered advisory without an accepted Policy declaration is not a Trial. No explicit decline record is needed. Existing fields such as `finalPolicyLastDeclaredAfter` and the derived "final policy exposure calls" are chronological post-declaration execution evidence only; the word *exposure* in legacy helpers must not be interpreted as provider delivery, model attention, material use or causality.

Do not add a new RunExperience schema solely for Trial attribution. At settlement, freeze the active assignment before clearing its one-Run runtime lease, commit the ordinary v5 Experience, obtain its exact record ID/fingerprint from the Experience-store commit boundary, then deterministically materialize immutable `TrialEvidence` when the application gates above pass. If Experience save fails, no TrialEvidence exists. If assignment lookup or exact binding is ambiguous, fail closed for learning and leave ordinary Task truth unchanged.

The reset likewise uses **`TrialEvidence` schema v2**; do not reinterpret the unused v1 shell whose fields encode the rejected exposure/eligibility model. TrialEvidence is factual support, not an evaluation verdict. Its v2 target shape contains exact v2 assignment/hypothesis/source refs, WorkEpisodeId, selected role/revision identity, bounded post-declaration execution counters, factual outcome/verification/error/cost fields and any exact comparison refs already available. Remove semantic/policy conclusions such as `exposed`, `eligible`, `eligibilityReason`, free-form `regressions` or a causal `used` flag. Versioned Evaluation gates decide whether factual evidence is eligible for a particular evaluation attempt. Materialized TrialEvidence protects the minimum exact support needed after raw Experience pruning.

The resulting lifecycle is:

```text
published executable StrategyHypothesis v2
  → real WorkEpisode exists
       ├─ already open at Run start
       └─ created by one same-Run task_start
  → atomic assign-if-absent chooses at most one hypothesis
  → one-Run overlay + one-shot transient advisory
       ├─ no exact policy declaration
       │    → ordinary Experience only
       └─ exact trial Policy declared + subsequent ordinary work
            → ordinary v5 Experience
            → deterministic immutable TrialEvidence
            → StrategyEvaluation:
                 promote | continue-testing | revise | reject
```

Independent Trial diversity is counted by WorkEpisodeId, while each TrialEvidence item names one exact Run Experience. At most one committed assignment exists per WorkEpisode in the initial reset architecture. No A/B control is required; these remain observational real-task Trials, so Evaluation must expose confounding and must never claim causal superiority.

### Rejected Trial implementation directions

1. **Provider/final-delivery instrumentation:** rejected. Pi 0.99.1 exposes mutable request transforms but no public immutable final-effective-request/delivery observer under arbitrary supported extensions. Transport-specific SSE/WS/cache/retry instrumentation is dependency-specific evidence about delivery mechanics, not a stable learning-domain boundary.
2. **T1 ahead-of-boundary zero-wait preparation:** rejected. Same-Run `task_start` coverage is useful, but it does not justify durable unbound reservations, filesystem eligibility watchers, speculative preflight, detached publication or the associated first-context race machinery. The simpler boundary waits only for bounded local `assignIfAbsent` after the real WorkEpisode exists, then uses a runtime-only transient projection before Pi continues.
3. **Separate experimental selection tool/state machine:** rejected. Pindie already has exact revision selector resolution, `pindie_policy_set`, PolicySnapshot attribution and post-declaration Run telemetry. A second selection path creates two competing meanings of "Strategy selected" and forces unnecessary synchronization.

## 6. Evaluation and autonomous trust

**R4-A foundation:** [EvaluationPacket v1 / EvaluationResult v1](autonomous-learning-r4-a.md) defines pure observational contracts and contract tests only. Exact immutable TrialEvidence v2 snapshots are the sole factual analysis inputs; live Experience (including raw comparison refs) is never read. Dedicated packet/result ref families remain separate from frozen StrategyEvaluation/Decision and grant no trust or Policy authority. No runtime execution, enqueue, publication or retention change is implemented. The following paragraphs remain the future execution/trust target, not R4-A runtime behavior.

An `evaluation` job starts a **separate native Pi Evaluation Run**, not the Discovery Run. Freeze an EvaluationPacket with exact hypothesis fingerprint, expected effect/failure signals, eligible and excluded TrialEvidence refs/fingerprints, available comparison facts with exact refs/fingerprints (or explicit absence), independent WorkEpisode/project diversity counts, factual outcome/error/verification/cost summaries and current trusted/lineage fingerprints. Harness owns factual gates and provenance; model interprets whether the observations support the predicted effect and contradictions, returning exactly one verdict: `promote | continue-testing | revise | reject` with bounded semantic rationale and cited packet handles. Store immutable StrategyEvaluation (structured verdict, evidence identities, packet fingerprint, gate version); no hidden reasoning persistence. These are observational real-task Trials: promotion means evidence supports advisory use under observed applicability conditions, **not** causal superiority. Expected effects and failure signals must be observable, but no A/B control is mandatory. Expose confounding, non-use and heterogeneity in the packet; when support is weak the model must choose continue-testing, revise or reject rather than treating missing comparison evidence as proof.

`continue-testing` and `revise` are Evaluation verdicts, not StrategyDecisions. A `revise` verdict enqueues the targeted `revision-discovery` job bound to this exact hypothesis and Evaluation; neither verdict changes portfolio trust. Autonomous `StrategyDecision` is a distinct immutable trust/portfolio transition for an exact hypothesis fingerprint and Evaluation ID when promoting/rejecting; suspend/reinstate bind the exact trusted revision and fresh evidence, while exceptional Human override records actor and scope. Promotion/rejection is legal only if current gates still pass: correct advisory schema/scope, complete uncorrupted source support (live or immutable evidence snapshot) and TrialEvidence support, minimum independent real trials, no disqualifying safety/contradiction signal, frozen provenance for any available comparison evidence (and explicit absence otherwise), sufficient observational support for advisory use, portfolio capacity, no conflicting decision/suspension, no changed base revision and available budget/authority. Model recommendation alone grants nothing. Reject on strong validated contradiction under deterministic gates; insufficient/ambiguous evidence yields a continue-testing verdict or targeted revision-discovery job, not false confidence. Terminal trust write is atomic/idempotent under lock; revalidate immediately before commit. Human approval is **not** needed for routine advisory trust, but Human controls global budgets and can exceptionally pause, suspend or override through explicit audited immutable decisions. Any future authority-changing concept is outside learnable Strategy and would require separate Human-approved design.

TrustedStrategyPortfolio is a runtime projection of valid Seeds + immutable hypotheses/evaluations/decisions, bounded by scope/capacity, containing only active exact trusted revisions in normal Runs with semantics, lineage, fingerprints and provenance. Experimental revision enters only through a valid assignment, never the trusted catalog. Normal model-owned `policy_set` advisory selection remains optional; no automatic default switch. Validate malformed or conflicting trust records fail closed (omit affected learned entries, surface diagnostic); no silent fallback to an untrusted revision. Global and local trust remain distinct; local trust never implies user-global trust.

## 7. Continuous refinement, consolidation and global hierarchy

Trusted usage produces ordinary factual Experience with exact revision attribution. Harness monitoring deterministically flags factual triggers: machine-observable declared failureSignals, verification regressions, or repeated error/cost/outcome facts against versioned factual thresholds over independent WorkEpisodeIds. Semantic failureSignals require model interpretation, not a Harness assertion. These triggers enqueue an urgent isolated evaluation-mode maintenance job; the model interprets semantic effectiveness or scope mismatch from bounded evidence in a cited degradation assessment, and only that fresh assessment plus deterministic trust/scope/evidence gates may create an advisory **suspend Decision**. This trusted-usage degradation assessment is distinct from the four-verdict StrategyEvaluation of an untrusted hypothesis; it does not add a fifth verdict. Direct Harness-only suspension is exceptional: a hard objectively machine-checkable integrity/safety contract violation (e.g. corrupted exact revision fingerprint or an attempted capability/permission expansion) may fail closed and record a cited suspend Decision without semantic interpretation. Loss of evidence alone fails closed for future promotion, not invented negative proof. Suspend removes the exact revision from active projection without erasing history or altering Task truth. A revision hypothesis names the exact base; its real Trials and evaluation use the same gates. Promoting it writes one Decision naming the exact prior trusted revision; projection derives that prior revision's superseded status atomically, without a separate supersede Decision; a rejected revision leaves a still-valid base trusted unless separately suspended. Reinstatement requires a new audited decision on fresh contradictory-to-suspension evidence and current safety gates, or promotion of a new revision; no expiry-based automatic reinstatement.

Low-frequency `portfolio-maintenance` jobs examine bounded trusted/open catalogs plus supporting evidence for overlap, duplicates and fragmentation. A consolidation proposal is an ordinary falsifiable hypothesis with lineage and baseline identities; it must obtain real Tasks, Evaluation and Decision, never rewrite/merge live Strategies directly. On full capacity, stop publication/promotion and report actionable pressure rather than silently evict history or an active Strategy.

Global discovery is **later-stage hierarchy**: local Experience → local discovery/trial/evaluation first. `global-discovery` consumes bounded conclusions from multiple independent **active trusted** project-local revisions (with valid promotion Decisions) **and** exact minimal supporting TrialEvidence/source provenance, not a raw multi-project Experience dump. Its packet freezes contributing project identities, exact active local revision/Decision fingerprints, diversity and comparison context; experimental local hypotheses are ineligible inputs. A global hypothesis has user-global scope but no global trust; test on suitable future real Tasks in multiple other projects, with explicit cross-project diversity and conflict gates. Local trust stays local; global trust is a new separately evaluated/decided scope. The legacy CPL v0.1 transfer and v0.2 synthesis artifacts retain their existing Human decision semantics during migration; do not reinterpret old approvals as v1 autonomous decisions or erase them.

## 8. Artifact families, integrity and recovery

| Family | Role | Persistence |
| --- | --- | --- |
| Experience | factual episodic evidence | bounded, prunable, namespace-scoped |
| WorkEpisodeId binding ledger / LearningJob / DiscoveryReceipt | operational identity, scheduling and dedupe, **not cognition or Task truth** | bounded durable ledger/receipts |
| StrategyHypothesis | immutable falsifiable cognition proposal | exact ID/fingerprint, append-only |
| TrialAssignment v2 | immutable WorkEpisode-scoped experimental scheduling binding to executable Hypothesis v2; presentation authority is one-Run runtime state | bounded version-separated assignment history |
| TrialEvidence v2 | immutable factual v2 assignment + exact Run Experience support; no provider-delivery/causal-use claim | append-only, protect decision support |
| StrategyEvaluation | immutable `promote | continue-testing | revise | reject` verdict with cited facts; no trust transition | append-only |
| StrategyDecision | immutable gated promote/reject/suspend/reinstate or explicit Human override; revision promotion names superseded exact revision | append-only |
| TrustedStrategyPortfolio | derived runtime projection, **not a store** | reconstruct on demand |

All artifacts are schema/versioned, size-bounded, namespaced, canonical-hashed and written exclusively after full validation; lock and atomic rename/unique creation guard concurrent writers. On restart, expire leases, reconcile job keys against receipts and exact outputs before retrying; never count a prior Pi response as committed cognition without its validated artifact. Duplicate delivery returns the same identity/result. Stale Session/project/generation discards uncommitted output. Interrupted Discovery/Evaluation resumes as the same job only after reconciling prior outputs; ambiguity/quarantine or malformed stores blocks that affected scope rather than fabricating a fresh result. An interrupted Trial never becomes eligible solely because an assignment exists. Partial/ambiguous writes fail closed; Human work is unaffected. Enforce single active learning Run across processes via durable lease/fencing; scheduling may continue after restart, not run duplicate cognition. No background daemon is necessary: safe idle Host opportunities suffice.

Budget per job, per day and per scope; packet/portfolio/record limits and exponential bounded backoff are versioned Human-configurable policy. No per-Task reflection tax. Notify only for repeated failures, exhausted budget needing Human action, capacity, corruption or exceptional override; do not announce each discovery/evaluation.

## 9. Migration from current implementation (not v1 compatibility requirements)

**Keep conceptually:** `run-experience.ts` / `experience-store.ts` factual bounded Experience and evaluation primitives; immutable artifact/fingerprint/provenance and exact revision trust patterns in SI v0.6/v0.7; CPL cross-project identity and trial evidence; `strategy-knowledge.ts` boundary and `strategy-portfolio.ts` projection. Revalidate schemas, retention and evidence gates before reuse; old Human decisions remain legacy trust facts, not automatic v1 Decisions.

**Replace:** explicit/admitted `/adapt`, `/derive`, `/derive-global`, `/trial` and Human `/promote`/`/reject` as the routine learning path with separate jobs, falsifiable hypotheses, real-task offers, Evaluation and autonomous advisory Decisions. The removed `learning-opportunity.ts` assessed a single accepted signal after settlement; old operational receipts, if present, remain on disk but are no longer read.
